# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ncpwsafe is a C++17 ncurses TUI (plus a few non-interactive CLI commands) for Password Safe V1/V2 database files. The actual file format/crypto lives in the external `libpwsafe` C library (`pwsafe.h`, `pws_*` functions, `PwsDbRecord`/`PwsFieldType`), not in this repo. `xclip` is required at runtime for clipboard copy.

## Build & test

```sh
cmake --preset=x64-linux-gcc-debug            # or x64-linux-clang-*, *-release; extra options: -DBUILD_TESTING=OFF, -DNCPWSAFE_DEBUG_SANITIZE=ON (ASan+UBSan, Debug only), -DUSE_GLOG=ON
cmake --build --preset=x64-linux-gcc-debug
./build/bin/ncpwsafe [DATABASE_FILE]          # executable goes to build/bin
./build/bin/ncpwsafe --help                   # CLI commands: --generate-password, --export-db, --change-password, --test-db (Debug only)

ctest --preset=x64-linux-gcc-debug            # all tests
ctest --preset=x64-linux-gcc-debug -R AppTest # tests matching a regex
ctest --preset=x64-linux-gcc-debug -L cli     # end-to-end CLI tests (-L tui: UI tests, -LE e2e: unit tests only)
./build/test/unittests --gtest_filter='AccountDbTest.*'   # run the gtest binary directly
```

- Presets (`CMakePresets.json`) all write to `./build`, so switching compiler or toolchain needs `--fresh`. Linux presets use the Unix Makefiles generator. The `x64-windows-msvc-*` presets use Ninja and vcpkg (`vcpkg.json`, overlay port `ports/ncurses`; the release preset uses the release-only overlay triplet `triplets/x64-windows-static-release.cmake`, which also links the C runtime statically (`CMAKE_MSVC_RUNTIME_LIBRARY` in the toolchain follows the triplet) so the executable needs no Visual C++ Redistributable, and glog is the manifest feature `glog`, selected in `CMakeLists.txt` when `USE_GLOG` is on), with `cmake/toolchain-windows-msvc.cmake` chainloaded through `VCPKG_CHAINLOAD_TOOLCHAIN_FILE`. The compiler, warning flags and debug flags come from `cmake/toolchain-*.cmake`, not from `CMakeLists.txt`. This mirrors the libpwsafe layout. Windows-specific code that needs the Windows SDK lives in `src/Win32.{h,cpp}`, which never includes `<windows.h>` alongside the curses headers. Elsewhere, prefer a platform `#ifdef _WIN32` in place, as long as it doesn't hurt readability; move code into `Win32.{h,cpp}` when the `#ifdef` would.

- `x64-linux-gcc-static-release` (`-DNCPWSAFE_STATIC_DEPS=ON`) is the build the Linux release package uses: ncurses, ICU and OpenSSL's libcrypto (which libpwsafe uses) are linked from their static `.a` libraries, and libstdc++ and libgcc with `-static-libstdc++ -static-libgcc` (on the `ncpwsafe` target only, the test executables link the shared GoogleTest), so the executable needs only glibc. `find_static_libraries()` in `cmake/ResolveDependencies.cmake` takes the libraries from pkg-config's `--static` flags and fails when a `.a` is missing. ICU's data library isn't linked in: the ICU functions ncpwsafe uses don't need it.
- System deps via pkg-config: the wide-character ncurses libraries ncursesw (+formw, menuw, panelw), icu-uc, OpenSSL (libcrypto, for libpwsafe), GTest (and libglog if `USE_GLOG`). `libpwsafe` and `libconfini` are pulled with `FetchContent` from the author's GitHub forks, pinned to commit hashes in `cmake/ResolveDependencies.cmake` (update the hash to take a change in a fork), so configuring needs network access. To develop against a local libpwsafe checkout, swap in the commented `SOURCE_DIR` line there.
- `gtest_discover_tests` sets the working directory to `${CMAKE_BINARY_DIR}/../test`, so tests expect the build directory to be a direct child of the repo root (e.g. `build/`).
- End-to-end tests need Python 3 (standard library only); the TUI tests also need tmux and are reported as skipped without it.
- CI (`.github/workflows/build.yml`) runs the `x64-linux-gcc-release` and `x64-linux-clang-release` presets on Ubuntu (configure, build, ctest).
- `CMakeLists.txt` rejects in-source builds (they leave `CMakeCache.txt`, `Makefile`s, `config.h` etc. in the source tree); use `build/`.
- `config.h` is generated from `config.h.in` into the build dir (app name/version, `HAVE_SYS_*` checks). The default preferences path, `~/.config/ncpwsafe/ncpwsafe.ini` (`%APPDATA%\ncpwsafe\ncpwsafe.ini` on Windows), is `DEFAULT_CONFIG_FILE` in `src/ProgArgs.cpp`.

## Architecture

- **Build layout**: every source file except `main.cpp` is compiled into the `libncpwsafe` OBJECT library, which links into both the `ncpwsafe` executable and the `unittests` gtest binary. New `.cpp` files must be added to the `SRC` list in `src/CMakeLists.txt`; new test files go in `test/CMakeLists.txt`.
- **Entry point** (`src/main.cpp`): parses `getopt_long` options into `InputProgArgs` (all `std::optional`), validates them, then `PWSafeApp::Init` turns them into a `ProgArgs` with defaults filled in. It then switches on `Operation`: `OPEN_DB` runs the TUI (`PWSafeApp::Show`), and the others run a `*Command` class (`ExportDbCommand`, `ChangeDbPasswordCommand`, `GeneratePasswordCommand`, `GenerateTestDbCommand`), each with `Execute()`. `ReadDbPassword()` reads the database password from `--password-file`, or prompts for it on the terminal for the commands that need one (opening a database prompts in the TUI instead); a new password (`--change-password`, `--test-db`) is always typed at the prompt, twice. Never take a password as an option value, where other users can see it. Adding a CLI option means touching the `options[]` table, `ParseArgs`, `ValidateArgs`, `Usage`, `InputProgArgs`, `ProgArgs`, the `DEFAULT_*` values in `ProgArgs.cpp`, and the man page.
- **`PWSafeApp`** is the central object, passed by reference to every window, dialog and command. It owns `ProgArgs`, the `AccountDb`, the root/accounts/command-bar ncurses windows, and database backup (rotation is controlled by the `Prefs` keys `backup-before-save` and `backup-count`).
- **Data model**: `AccountDb` (pathname, password, read-only flag) wraps `AccountRecords`, a collection of `AccountRecord` maps keyed by `PwsFieldType` with dirty tracking. `ReadDb`/`WriteDb` convert to and from libpwsafe's linked-list `PwsDbRecord`. Return codes use `ResultCode` (which extends libpwsafe's `PRC_*` codes) through an optional `int *rc` out-param plus `SetResultCode()`.
- **TUI**: built on ncurses `panel`, `menu` and `form`. `AccountsWin` is the main window, a one-column list of accounts under a collapsible heading for each group; it draws the rows itself (the `menu` library can't style single items). The rows, the selection, collapsing and scrolling are kept by `AccountList`, which has no ncurses code and is unit-tested; rows point to `AccountRecord`s, so rebuild it with `Build()` whenever the records change. `Dialog` is a generic form dialog built from a `std::vector<DialogField>`, with validate/discard/input-delegate callbacks; specific dialogs (`AccountDetailsDlg`, `ChangePasswordDlg`, `SafeCombinationPromptDlg`, ...) build on it. A field of more than one row (`DialogField::m_height`, the notes) is a `TextArea`, a unit-tested model with no ncurses code that `Dialog` draws over an empty form field: form fields drop line breaks, tabs and wide characters past the first row, and change values they can't show, so one-row fields keep the value they were given until they are edited (`field_status()`). `MessageBox`, `CommandBarWin`, `SearchBarWin` and `HelpWin` complete the set. Register every key of a window with `CommandBarWin::Register()` and give it a description: the command bar ends with `^G More` when they don't all fit, and `HelpWin` lists them all. Modal loops that own a command bar handle `KEY_CTRL('G')` with `app_.GetCommandBar().ShowHelp(win_)` (not F1, which many terminals and window managers keep for their own help). Draw text with the semantic roles of `Theme` (`app_.GetTheme().Attr(Role::HEADING)`, or `ScopedAttr`), never raw attributes or colour pairs: `Theme` picks colour or a monochrome fallback (`NO_COLOR`, `theme = mono` pref), keeps a non-colour cue for every role, and always draws the selection in reverse video, which the TUI tests rely on. Use only the 8 basic colours. Each component runs its own modal loop, which must read keys with `ReadKey()` (`wget_wch`), never `wgetch()` directly: non-ASCII characters reach `form_driver_w()` whole, and the auto sign-off timer runs.
- **Auto sign-off** (`AutoSignOff.{h,cpp}`): after the `auto-sign-off` pref's period without a key press (default `5m`, `0` is off), `ReadKey()` throws `AutoSignOff`. It unwinds every open window and dialog to `PWSafeApp::Show()`, which wipes the database from memory (`AccountDb::Wipe()`) and clears the screen; `main()` prints a message and exits 124 (`EXIT_AUTO_SIGN_OFF`). The timer uses `CLOCK_BOOTTIME` (`GetTickCount64()` on Windows) so time asleep counts. A loop that holds secrets or ncurses resources must still release them when `AutoSignOff` passes through it (see `Dialog::Show()`, which scrambles its fields and rethrows).
- **Terminal resize**: every modal loop must handle `KEY_RESIZE` by calling `app_.HandleResize()`, and must register its own relayout for the length of the loop with `ScopedResizeHandler resize_handler(app_, [this]() { OnResize(); });`. Handlers form a stack and run bottom-to-top so stacked panels lay out in order. Follow this pattern in any new window or dialog.
- **Text encoding**: account text is UTF-8. `main()` calls `SetUtf8CtypeLocale()`, which uses a UTF-8 `LC_CTYPE` (falling back to `C.UTF-8`) even when the user's locale isn't UTF-8, because the wide ncurses libraries need it to show and edit non-ASCII text. Convert to ICU with `icu::UnicodeString::fromUTF8`.
- **Prefs**: a `Prefs::Instance()` singleton backed by an INI file (libconfini), with typed `Get<T>`/`Set<T>`.
- **Secrets hygiene**: `Dialog::RandomizeBuffers()` scrambles form buffers and `Utils.cpp` zeroes memory through a volatile `memset` pointer. `PromptForPassword()` (`PasswordPrompt.{h,cpp}`, the console version in `Win32.cpp`) reads a password from `/dev/tty` (`CONIN$`) with echo off, and restores the terminal when a signal or Ctrl+C ends the process at the prompt. Keep these when touching password-handling code. In Release builds only (`NDEBUG`), so a debugger can still attach to Debug builds, `main.cpp` calls `prctl(PR_SET_DUMPABLE, 0)` to block ptrace and core dumps, or on Windows `win32::DisableCrashDumps()` to keep Windows Error Reporting from writing crash dumps and `win32::RestrictProcessAccess()` to keep other processes from opening it.

- **Man page**: `man/ncpwsafe.1.in`, written by hand in mdoc(7). `man/CMakeLists.txt` fills in the version with `configure_file()` (to `build/man/ncpwsafe.1`; preview with `man -l build/man/ncpwsafe.1`) and installs it. Changing a command-line option, a key, a screen, a preference, an environment variable or an exit status means updating the page in the same change. `cli.man_page` checks that every option in `--help`, every key in a command bar `Action` list and every key constant in `Prefs.h` is documented, and lints the page with mandoc or groff; it can't check that the descriptions are still right.
- **README screenshots**: `docs/images/accounts-list.png` and `edit-account.png` show the made-up accounts of `test/e2e/fixtures/screenshot.tsv`. A UI change that makes them out of date means taking them again with `python3 docs/images/make-screenshots.py` (needs a build with the tests, tmux, Chrome or Chromium and ImageMagick) in the same change. Never take them from a real database.

## Testing conventions

- GoogleTest. To reach private members, classes declare `FRIEND_TEST(...)` under `#ifdef FRIEND_TEST` (see `PWSafeApp.h`, `AccountDb.h`). A new test that needs private access must add a matching `FRIEND_TEST` declaration in the class header.
- Filesystem access goes through the virtual `Filesystem` struct (`Filesystem::instance` by default), which is injected into `PWSafeApp`'s constructor so tests can pass a mock (see `FilesystemMock` in `test/PWSafeApp-tests.cpp`). Prefer this over calling `std::filesystem` directly in code that needs testing.
- `test/README.md` documents the tests in detail. Keep it current when changing the test layout or helpers.
- When adding or changing behaviour, follow "Choosing a kind of test" in `test/README.md`: unit-test logic that can be checked without a terminal, and use CLI or TUI end-to-end tests for what only shows through the command line or the UI. For a bug, add a test that reproduces it at the lowest level that can, plus an end-to-end test if the bug only showed through the CLI or UI.
- **End-to-end tests** live in `test/e2e/`: `cli/test_*.py` run the CLI commands, `tui/test_*.py` drive the ncurses UI in a private detached tmux server (`tmuxdriver.TmuxApp`). Each file is one CTest test named `cli.<name>`/`tui.<name>` (labels `e2e` plus `cli` or `tui`), registered by a glob in `test/e2e/CMakeLists.txt`. They're Python `unittest`, standard library only; base classes and helpers are in `test/e2e/e2elib.py`.
  - Test databases are built per test by the `e2e-mkdb` helper (`test/e2e/mkdb.cpp`) from `fixtures/*.tsv`. They aren't committed, and the tests don't use `--test-db`, which is Debug-only. Check results with `--export-db` (`assertDbContains`).
  - Each test case gets a temp directory (under `/tmp` on Linux) that is also `$HOME` (and `%USERPROFILE%`/`%APPDATA%` on Windows), so preferences and backups stay out of the real home directory.
  - The CLI tests run on Linux and Windows (MSVC build); keep them portable (`pathlib`, `e2elib.IS_WINDOWS`, `assertNotCrashed`). The TUI tests are skipped on Windows (no tmux).
  - In TUI tests, wait for the screen (`wait_for`, `wait_gone`, `wait_highlighted`) after sending keys; never sleep. `highlighted()` returns the name of the selected row (the reverse-video text up to a gap of two spaces, without the `▾`/`▸` heading marker), e.g. `Chequing` or `Banking`. Line drawing appears as ACS letters (`lqk`, `x`, `mqj`): ncurses uses them on `TERM=screen`, or Unicode box drawing in a UTF-8 locale, which `tmuxdriver` translates back.
  - `run_ncpwsafe()` runs ncpwsafe without a terminal, so a password prompt fails instead of waiting; `start_on_terminal()` runs it on a pseudo-terminal (`e2elib.TerminalApp`) to answer prompts (`answer(prompt, text)`), and those tests are skipped on Windows (`e2elib.HAS_PTY`).
  - The clipboard is a stub that `NCPWSAFE_XCLIP` points to. xclip runs with only `DISPLAY`/`XAUTHORITY` in its environment, so the stub has its output path written into it.
  - A script that can't run (no tmux, Release build for `--test-db`) exits 77, which CTest reports as skipped.
  - Tests of known bugs are `@unittest.expectedFailure`, with a comment describing the bug. Remove the decorator in the same change that fixes the bug.
  - UI changes (key bindings, messages, dialog titles or fields) usually need matching changes to the TUI tests.
- `src/en_CA.dat` and `src/ru.dat` are word lists written as C string literals and `#include`d directly into `GenerateTestDbCommand.cpp`. `--test-db` uses them to generate test databases (`--test-db-lang=en-CA|ru`).

`docs/dev-plan.md` tracks planned features and the to-do backlog (§3), and `docs/ISSUES.md` has detailed write-ups of known bugs.
